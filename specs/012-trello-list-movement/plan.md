# Plan and contracts

Significant native-provider/API/MCP/UI boundary extension. Existing dirty work is preserved, no commits or dependencies. Prior durable workflow rules apply: pending-before-write journal, source revisions, stable operation IDs and uncertain receipts. Use Spec Kit, Graphify impact/source verification, RED→GREEN tests and independent composition review.

Current documentation verified with Context7 against Atlassian: GET board lists with open filter; PUT card with idList only; remote list exposes idBoard/closed. Card closed and list membership are independent. Sources: https://developer.atlassian.com/cloud/trello/rest/api-group-cards/ and https://developer.atlassian.com/cloud/trello/rest/api-group-boards/.

Provider unit: Trello plugin projects `idBoard` and `idList` in issue data. Existing defaultListId config-field loadOptions provides active lists for a board via existing authenticated PluginHttp. updateIssue handles move payload `{idList,expectedListId,expectedBoardId}` separately from title/state: validate current card and open destination list on expected board immediately before PUT; reject mixed status/title changes; send only idList. Unit tests cover mismatches, archived destination/card policy, credential-safe errors and unchanged existing writes.

Host unit: WorkflowIntegrationService delegates to WorkflowTrelloService, using the registered provider's existing loadOptions + PluginHttpService with native headers; projects boardId/listId and lists `{id,name,supported}`. New integration.move preflights remote expected identifiers and fresh open-list membership, calls the native provider's updateIssue with the above move payload, and guards its actual PUT with authorization/journal/native fences after asynchronous provider preflight. Other HTTP mutation methods are blocked for this explicit move. Re-read the card to verify exact list/board and unchanged archived state, then existing native linkage-only bookkeeping. No native task movement/completion follows a remote list change. This uses the native definition directly so authorization can be rechecked at PUT, rather than only before the generic adapter's whole asynchronous operation.

Contract unit: add command to shared type/MCP schema, write grants, pure-core integration routing/declarations as needed. UI adds dedicated list-move form and expected snapshot fields; preserve independent state-sync form. Existing operation receipts and unknown-outcome handling remain authoritative.

Validation: provider Vitest/typecheck, host focused Angular tests, MCP/core/browser suites, file checks, production build, architecture/composition/diff review and Graphify refresh. Package both Trello bundled assets and planner ZIP; install host and planner without enabling a provider or modifying grants. Verify original tasks/settings/grants unchanged, no live Trello writes.
